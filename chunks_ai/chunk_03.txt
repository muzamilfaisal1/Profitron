The data layer's design is worth presenting in detail because its correctness is a precondition for everything downstream and because its failure modes are the most common source of operational issues we encountered during development. The principal goal of the data layer is to convert a noisy, asynchronous, occasionally unreliable stream of exchange messages into a clean, well-validated tabular feed that downstream components can consume without having to handle exchange-side quirks. The cost of getting this conversion wrong is not merely an occasional dropped message; it is a silently corrupted view of the market that the agent then makes decisions on. Several distinct design considerations interact to produce a robust data layer, and we describe each in turn.

The data layer opens a persistent WebSocket connection to the target exchange — in our primary deployment, Binance — and falls back to a REST poller when the socket drops. Incoming ticks are timestamped against an NTP-synchronised local clock so that downstream logic can reason about wall time rather than whatever the exchange chooses to report. A thin validation stage rejects out-of-range or duplicate messages before the tick is appended to a rolling in-memory buffer and, at a coarser frequency, flushed to persistent storage for post-hoc analysis and backtesting. The rate-limit policy is adaptive rather than fixed: the layer keeps a sliding estimate of the exchange's observed tolerance and throttles request bursts pre-emptively when the estimate approaches the stated ceiling, avoiding the common failure mode in which a naive poller triggers an IP ban during a volatile session precisely when the agent most needs fresh data.

The complete flow from exchange tick to executed order is illustrated in Figure 4, which foregrounds the loop-back from trade feedback into model updates and risk recalibration. This feedback path is the reason the system can adapt to changing market conditions without manual retuning. The arrows in the figure represent the canonical happy-path; the system also implements explicit error paths for each transition, with bounded retry policies that we tuned empirically based on the observed reliability of the upstream service.

A subtle but important design choice in the data layer is the separation of the rolling in-memory buffer from the persistent SQLite store. The in-memory buffer is sized to hold approximately twenty-four hours of minute-scale data — enough for the rolling features the model consumes — and is updated at full tick cadence. The persistent store is updated at one-minute aggregation cadence, which reduces disk write volume by approximately three orders of magnitude relative to a naive implementation that wrote every tick. The trade-off is that a crash mid-minute loses up to sixty seconds of data, but this is acceptable in our context because the data is not the source of truth for trade state; the exchange itself is.

A second choice worth elaborating concerns timestamp normalisation. The Binance API reports timestamps in millisecond precision but with non-trivial clock drift relative to the wall clock on the agent's host. We synchronise the host clock against an NTP server every five minutes and apply a per-message correction to the exchange-reported timestamp before the message enters the buffer. The correction is small in absolute terms — typically a few tens of milliseconds — but it materially improves the consistency of the time-series features computed downstream, because rolling statistics computed over inconsistently timestamped windows can introduce artefactual jumps that the model then learns to chase.

A third design decision concerns the handling of dropped ticks. When the WebSocket connection is briefly interrupted, the agent loses access to the ticks that occurred during the interruption window. We detect this condition by comparing the timestamp of the first message after reconnection against the expected next-tick timestamp; if the gap exceeds a threshold, the agent issues a backfill request to the REST API to retrieve the missing data. The backfilled data is reconciled against the in-memory buffer with explicit tagging that distinguishes backfilled ticks from live ticks, so that any downstream logic that depends on the timing of the original message receipt can avoid using backfilled data inappropriately. The reconciliation logic is one of the more subtle pieces of the data layer and was the source of several bugs early in development; it is now thoroughly tested but worth flagging as a non-obvious source of complexity.

A fourth consideration is the rate at which the agent emits requests to the exchange. Binance's public rate limits are documented per minute, but the practical limits depend on the type of endpoint accessed and on whether the user's account has been flagged for any reason. We implement a token-bucket rate limiter that enforces a conservative cap below the documented limit, with separate buckets for read-only and write endpoints. The conservative cap costs us some throughput in normal conditions but provides a safety margin against sudden spikes in demand that could otherwise trigger an IP-level rate-limit response from the exchange.

4.3 Technical Indicator Feature Set

Before any learned model sees the data, a feature engineering stage computes a small panel of technical indicators and concatenates them with the raw OHLCV series. The choice of indicators was deliberately kept modest to avoid the high-variance, easily overfit feature sets that characterise many hobbyist projects. We chose three principal indicator families and supplemented them with the raw price and volume streams; we discuss the rationale for each family in turn.

The first family of indicators captures trend state through simple and exponential moving averages. The construction of these indicators is elementary — a moving average is a sliding mean — but their combination provides a surprisingly compact description of the regime. Figure 5 illustrates a twenty- and fifty-period simple moving average overlaid on the raw candlesticks for an ETH/USDT sample window. The two lines capture short- and medium-horizon trend state, and the distance between them, together with their slopes, provides the model with a low-dimensional description of the prevailing trend regime without requiring it to learn the concept from raw prices.

A subtle but important property of moving averages is that they introduce a known phase lag that the model can in principle correct for. A twenty-period simple moving average lags the underlying series by approximately ten periods — half its window — which means that signals derived from it are inherently delayed. The model can learn to anticipate this lag, but the more important effect is that a strategy that trades on raw moving-average crossovers will systematically enter trends after they have begun and exit them after they have ended. This is a feature, not a bug: the lag is what filters out short-term noise and ensures that the strategy commits to a position only when the underlying signal has reached a level that suggests durability.

The second family of indicators captures momentum. The Relative Strength Index, plotted in Figure 6, contributes a bounded oscillator whose value can be combined with the unbounded trend features without scaling difficulty. The conventional overbought and oversold thresholds at seventy and thirty provide the strategy engine with natural tripwires that, when confirmed by other indicators, trigger entries or exits.

The RSI is a particularly useful complement to the trend features because its behaviour is qualitatively different in different regimes. During a strong trend, the RSI tends to spend extended periods in the overbought or oversold zone and the conventional threshold-crossing signals are unreliable; a trader who blindly sells every time the RSI crosses seventy in a strong uptrend will repeatedly cut profits short. During a range-bound regime, conversely, the RSI tends to oscillate cleanly between extremes and the threshold signals are reasonably accurate. The model learns to weight the RSI signal appropriately based on the prevailing regime, which is an example of the kind of contextual reasoning that would be cumbersome to encode in an explicit rule but emerges naturally from supervised learning on a representative dataset.

The third family of indicators captures realised volatility. Bollinger Bands, plotted in Figure 7, place two standard-deviation bands around a twenty-period moving mean and give the model a direct estimate of volatility alongside a contextual reading of whether the current price is stretched. When the bands are narrow, volatility is low and the agent can afford tighter stops; when the bands widen, the agent's stop-loss logic automatically expands to avoid being shaken out by noise.

Bollinger Bands also encode information about the persistence of volatility regimes. Empirically, periods of low volatility tend to cluster (the so-called "volatility clustering" property documented in many financial time series), and periods of high volatility likewise cluster. The width of the Bollinger Bands at the current step is therefore a useful predictor of the width of the bands at the next step, and the model learns to incorporate this persistence into its forecasting horizon. A practical consequence is that the agent's confidence in its directional signal is generally higher during low-volatility regimes than during high-volatility regimes, even when the directional signal itself is the same, because the expected magnitude of the next move is more predictable.

4.4 Mathematical Definitions of the Indicator Panel

For the sake of reproducibility we record the precise mathematical definitions of the indicators used in the production system. Let p_t denote the close price at time step t, h_t and l_t the high and low, and v_t the volume. The simple moving average over a window of length n is defined in the conventional way as the arithmetic mean of the most recent n closes. The exponential moving average over the same window is defined recursively, with the smoothing factor alpha set to two over n plus one and the recursion initialised at the simple moving average over the first n samples.

The Relative Strength Index over a window of length n is defined as one hundred minus one hundred divided by the quantity one plus the relative strength, where the relative strength is the average of positive price changes over the window divided by the average of absolute negative price changes over the same window. The conventional choice of n is fourteen, which we retain in the production system. Bollinger Bands consist of a middle band given by the n-period simple moving average and an upper and lower band offset from the middle band by two standard deviations of the most recent n closes; the conventional choice of n is twenty, which we also retain.

The Moving Average Convergence Divergence indicator is defined as the difference between two exponential moving averages, conventionally with windows of twelve and twenty-six periods. The signal line is then a nine-period exponential moving average of the MACD line itself, and the histogram is the difference between the MACD line and the signal line. All three quantities — the MACD line, the signal line, and the histogram — are exposed as features to the model.

The Average True Range over a window of length n is defined as the moving average of the true range, where the true range at each step is the maximum of the high-low spread, the absolute difference between the high and the previous close, and the absolute difference between the low and the previous close. The conventional window length is fourteen periods, which we retain. ATR is the principal input to the volatility-scaled stop-loss logic discussed below.

4.5 Mathematical Formulation of the LSTM

The LSTM cell at time step t computes its hidden state h_t and cell state c_t through the standard four-equation update. The forget gate f_t takes the concatenation of the previous hidden state h_(t-1) and the current input x_t through a sigmoid-activated linear projection; the input gate i_t and candidate cell update c-tilde_t are computed analogously, with the candidate using a hyperbolic-tangent activation rather than a sigmoid; the new cell state c_t is the element-wise sum of the gated previous cell state and the gated candidate; and the new hidden state h_t is the element-wise product of the output gate o_t and a tanh-transformed view of the new cell state. The four gates each have their own learnable weight matrices and bias vectors, and the total parameter count of a single LSTM layer with input dimension d_in and hidden dimension d_h is approximately four times the product d_h times d_h plus d_in plus one.

In our two-layer stack, the input to the first layer is the fourteen-dimensional feature vector at the current time step, and the input to the second layer is the hidden-state output of the first layer at each time step. Both layers use a hidden dimension of fifty, which gives the full network approximately twenty-six thousand learnable parameters — small enough to train efficiently on commodity hardware and large enough to represent the temporal patterns the indicator panel encodes.

4.6 The LSTM Forecaster

The processing layer subscribes to the rolling buffer maintained by the data layer and, on each new window, produces a directional forecast and a magnitude estimate. The model at the core of this layer is a two-layer stack of Long Short-Term Memory cells. The layer-wise architecture is shown in Figure 8. The input is a sliding window of sixty minutes, each step carrying the multi-dimensional feature vector described above. The first LSTM layer returns the full sequence to the second layer, which returns only the final hidden state. A dense layer with sixteen units and ReLU activation then maps the hidden state to a three-way softmax output (up, flat, down) and a parallel linear output estimating the expected magnitude of the next-period move. Dropout of 0.2 is applied after each recurrent layer, and batch normalisation at the input stabilises training in the presence of the wide dynamic range characteristic of raw price series.

The choice of two stacked LSTM layers rather than one or three is the result of pilot experiments. A single-layer LSTM, even with a larger hidden state, consistently underperformed the two-layer version on the validation slice; we attribute this to the fact that the second layer can extract higher-level temporal abstractions from the first layer's outputs, including pattern compositions that would be difficult for a single layer to represent in the same parameter budget. Three or more layers, by contrast, did not produce statistically significant improvements over two layers and exhibited noticeably greater training instability. The two-layer configuration is therefore both effective and robust to the kinds of hyperparameter perturbations that a non-specialist user might inadvertently introduce.

The decision to use a softmax over three classes — up, flat, down — rather than a regression on the next-period return was driven by two considerations. First, a discrete classification head has a more interpretable confidence score than a regression head, which is important for the downstream rule that suppresses trades below a confidence threshold. Second, the asymmetric trading economics of the underlying market mean that small return predictions are not actionable: a regression that predicts the next-period return will be plus or minus a few basis points is correct about its magnitude but gives no useful signal about whether to act, because the round-trip transaction cost is comparable. The flat class explicitly absorbs these unactionable cases and allows the strategy engine to skip them cleanly.

The parallel regression head on the expected magnitude is retained because it provides a useful auxiliary signal for position sizing. A high-confidence directional prediction with a small expected magnitude warrants a smaller position than a high-confidence directional prediction with a larger expected magnitude, and the regression head provides the input that allows the position sizer to make this distinction.

4.7 Loss Function and Optimisation

The training objective combines a categorical cross-entropy term for the directional classification head with a mean-squared-error term for the magnitude regression head. The combined loss is a weighted sum, with the classification term weighted at 0.75 and the regression term at 0.25. The choice of weights was made empirically: heavier weighting of the classification head produced a model whose direction was reliable but whose magnitude estimates were poorly calibrated, while heavier weighting of the regression head produced the opposite pathology. The 0.75/0.25 split delivered the best joint behaviour on the validation slice.

Optimisation uses the Adam algorithm with beta-1 of 0.9, beta-2 of 0.999, and an initial learning rate of one times ten to the negative third. Gradient clipping at a global L2 norm of one is applied at every step to mitigate the gradient-explosion problem that occasionally affects recurrent networks. Mini-batch size is one hundred and twenty-eight, chosen as a balance between training-set utilisation and per-step computation time. The full training run takes approximately three hours on a single mid-range CPU and approximately twenty minutes on a single mid-tier GPU.

4.8 Strategy Engine and Risk Controls

The prediction is fed into the strategy engine, which applies the user-configured trading rule to decide whether to act. The engine is intentionally conservative: it produces a trade only when the softmax probability for the winning class exceeds a configurable threshold (by default, 0.70), when the estimated magnitude exceeds the round-trip transaction cost, and when the current position sizing is within the user's risk budget. Risk is enforced as a hard ceiling of two percent of account equity per trade, with dynamic stop-loss levels scaled to recent volatility. A circuit breaker halts all trading for a configurable cool-down period when realised volatility exceeds a threshold, when the consecutive-loss count exceeds a threshold, or when the balance reaches a daily loss limit. These controls are not optional overlays; they are mandatory gates in the execution path and cannot be bypassed without editing the configuration file and restarting the agent.

The asymmetry between the bounds on individual trade losses and the bounds on individual trade gains is deliberate. A stop-loss caps the worst-case outcome of a trade at a known fraction of equity; a take-profit, if used, would cap the best-case outcome symmetrically. We have chosen not to use a fixed take-profit because the asymmetry of trading economics — small wins are barely worth taking, large wins are disproportionately valuable — argues for letting winners run as long as the signal that initiated the trade remains valid. The exit logic for winning trades is therefore based on the model's continuing endorsement of the position rather than on a price-based take-profit threshold. Specifically, a winning position is closed when the model's confidence in the entry direction falls below a continuation threshold or when a trailing stop is triggered, whichever occurs first.

The volatility-scaled stop-loss is the single most consequential risk control in the system. Conventional fixed-percentage stops perform poorly across regimes because their effective tightness depends on the current volatility; a stop set at one percent below entry is restrictive in a quiet market but laughably loose in a volatile one. The volatility-scaled stop sets the distance to a configurable multiple of the recent Average True Range, so that the effective tightness of the stop is approximately constant in volatility-adjusted terms. The practical effect is that the agent is rarely stopped out by ordinary intraday noise but is reliably stopped out when the underlying signal genuinely fails.

4.9 Algorithm Specification

We summarise the agent's main decision loop in the following algorithmic terms. At each tick arrival, the data layer first validates and timestamps the incoming message and appends it to the rolling buffer. If a full minute has elapsed since the last feature computation, the processing layer computes the indicator panel over the most recent sixty-minute window, normalises the resulting feature vector against the running statistics from training, and submits the vector to the LSTM forecaster. The forecaster returns a three-way softmax probability vector and a magnitude estimate. The strategy engine inspects these outputs against the current trade state, the user's risk parameters, and the prevailing volatility regime, and produces one of four decisions: open a new position, close an existing position, modify the stop-loss level on an existing position, or take no action. The decision, if it requires submission of an order, is passed to the execution layer, which selects an appropriate order type, applies any necessary slicing, submits the order to the exchange, and reports the result back through the message bus. The notification subsystem listens for trade events on the bus and forwards them to the operator through the messaging interface. All state-changing operations are persisted through the database manager before they are acted on.

The risk-gating logic deserves separate elaboration because it is the most consequential decision point in the system. When the strategy engine proposes an action, the risk gate first checks that the proposed position size is within the user's daily exposure limit; if not, the action is rejected and a notification is sent. The gate then checks that the realised volatility over the past hour is within the configured tolerance; if volatility exceeds the threshold, the action is converted into a "no-action" decision. The gate then computes a volatility-scaled stop-loss distance and verifies that placing the proposed order with this stop-loss would not exceed the per-trade risk budget; if it would, the position size is reduced to the maximum that fits within the budget. Finally the gate checks that the consecutive-loss counter is below the cool-down threshold; if not, the action is suppressed for a configurable duration. Only if all four checks pass is the action forwarded to the execution layer.

4.10 Training Protocol

The LSTM was trained on roughly five years of one-minute OHLCV candles for ETH/USDT and a small basket of large-cap equities. The window covered a range of regimes, including two extended uptrends, a sustained drawdown in 2022, and several high-volatility macro events. We intentionally retained the stressful periods rather than cleaning them out, since the purpose of the model is to survive such periods rather than to post flattering numbers on placid data.

Training proceeded with a walk-forward protocol illustrated in Figure 9. The earliest seventy percent of the data was used for initial fit, the next fifteen percent for validation and early stopping, and the final fifteen percent held out for evaluation. We then slid the window forward in monthly increments, retraining each time, to produce a realistic estimate of live performance rather than the optimistic look-ahead-biased estimate that a single train/test split would yield. The walk-forward protocol is more computationally expensive than a single split — it requires re-training the model on each slide — but it produces an estimate of out-of-sample performance that is materially closer to what the agent will actually achieve in live deployment.

The classification head was trained with categorical cross-entropy, the regression head with mean squared error on log-returns, and the combined loss weighted to give the classification task three-quarters of the gradient. The Adam optimiser was used with an initial learning rate of one times ten to the negative third and a cosine-annealing schedule that decays to near zero over fifty epochs. Cosine annealing was chosen after brief experimentation with step decay and exponential decay; the three schedules produced similar terminal accuracy, but cosine annealing delivered the smoothest validation-loss curves and was the easiest to pair with warm restarts in longer runs.

The training data was preprocessed in the obvious ways: prices were transformed to log-returns to stabilise variance across regimes, technical indicators were standardised to zero mean and unit variance using statistics computed only on the training fold, and the resulting feature vectors were normalised within each sample window to remove residual scale dependence. Class labels were assigned by thresholding the next-period return: returns above a small positive threshold were labelled "up", returns below a small negative threshold were labelled "down", and returns within the band were labelled "flat". The thresholds were chosen so that the three classes were approximately balanced over the training window, which simplified the loss-weighting analysis.

The label-smoothing regularisation technique was applied to the categorical cross-entropy loss with a smoothing factor of 0.05. Label smoothing distributes a small fraction of the probability mass from the correct class to the incorrect classes, preventing the model from becoming over-confident in its predictions and improving calibration of the resulting confidence scores. The choice of 0.05 was empirical; smaller values produced models with sharper but less calibrated predictions, and larger values produced models whose predictions were too diffuse to drive useful trading decisions.

We also experimented with several data-augmentation strategies during training, including time-warp transformations of the input window and additive Gaussian noise injection on the input features. Neither augmentation produced a statistically significant improvement on the validation slice, and we chose to omit them from the production training pipeline to avoid the additional complexity. The negative result is itself informative: it suggests that the model is not data-starved in the way that augmentation typically helps mitigate, and that further accuracy gains will need to come from feature engineering rather than from training-data manipulation.

A separate consideration during training was the management of the class imbalance that emerges in non-trending market windows. When a particular training fold happens to contain a long range-bound period, the flat class becomes over-represented relative to the directional classes, which biases the model toward predicting flat. We addressed this by computing per-class weights inversely proportional to the empirical class frequency on each fold, which in practice gives the directional classes higher loss weight during folds with long range-bound periods. The reweighting is applied only at training time; at inference time the model produces unweighted probabilities that the strategy engine then thresholds.

4.11 Hyperparameter Selection

The principal hyperparameters of the LSTM — the number of hidden units per layer and the dropout rate — were selected by a coarse grid search on a held-out validation slice. Figure 10 summarises the outcome. Fifty units with 0.2 dropout produced the best validation accuracy, a result consistent with prior work on similar horizons. The gradient of the surface is shallow in the neighbourhood of the optimum, suggesting that exact tuning is less important than being somewhere in a reasonable region, but the edges of the surface (zero dropout, or very large hidden state) degrade sharply.

The shallow gradient observation has practical implications for users who wish to retrain the model on a different asset or a different time horizon. The conventional advice in such cases is to perform a fresh hyperparameter search; our experience is that the default values continue to perform well across reasonably similar settings, and that the dominant risk is not suboptimal hyperparameters but suboptimal feature engineering or insufficient training data. We therefore recommend that users start with the default values, evaluate the resulting model, and only resort to hyperparameter search if the default-tuned model exhibits clear pathological behaviour.
